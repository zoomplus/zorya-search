# Начало работы с Zorya Search

Руководство устанавливает доступный архив GitHub `v0.1.6`. Новые API текущих исходников перечислены отдельно: они пока не входят в этот архив. Пакет в npm registry не опубликован.

## 1. Установите архив

Нужен Node.js `>=20.19.0`. Установите закреплённый архив в проект, который будет владеть Search:

```sh
npm install --save-exact https://github.com/zoomplus/zorya-search/releases/download/v0.1.6/zorya-search-0.1.6.tgz
```

## 2. Создайте конфигурацию один раз

Выберите **один** вариант первой настройки. Оба создают конфигурацию в стандартном пользовательском каталоге и не меняют профиль клиента.

### Только локальный лексический поиск

```sh
npm exec -- zorya-search setup --root .
```

### Code profile и web discovery

Если нужны embeddings/reranking для кода и поиск ссылок Brave, задайте их при создании той же конфигурации:

```sh
npm exec -- zorya-search setup --root . \
  --code-env OPENROUTER_API_KEY \
  --web-env BRAVE_SEARCH_API_KEY
```

Эти команды — альтернативы; не выполняйте обе. Они передают только имена переменных. Значения `OPENROUTER_API_KEY` и `BRAVE_SEARCH_API_KEY` должны быть доступны процессу-владельцу, но не передаются в командной строке или клиентском JSON. Включённый code profile может отправлять фрагменты и поисковые запросы выбранному провайдеру; без него кодовый поиск остаётся локальным и лексическим. Web discovery и web embedding настраиваются отдельно друг от друга.

Если нужна нестандартная конфигурация, задайте один и тот же путь через `--config` всем последующим командам:

```sh
npm exec -- zorya-search setup --config /absolute/path/runtime.json --root /absolute/path/repository
npm exec -- zorya-search client-config --config /absolute/path/runtime.json
npm exec -- zorya-search index --config /absolute/path/runtime.json
```

Каталог конфигурации и `dataDir` должны находиться вне индексируемого корня. Дополнительные профили и лимиты описаны в [руководстве CLI](cli.md).

### Если конфигурация уже существует

`setup` не перезаписывает существующий файл. Не запускайте setup повторно с тем же путём. Если служба работает, сначала остановите её через `npm exec -- zorya-search service --stop --config /absolute/path/runtime.json` (для стандартного пути можно убрать `--config`), затем безопасно сохраните резервную копию и измените существующий runtime JSON согласно [схеме и профилям CLI](cli.md). Сохраните прежние `dataDir`, roots и остальные настройки; после правки перезапустите тот же экземпляр службы обычным способом. Для `client-config`, `index` и `service` продолжайте использовать тот же `--config` путь. Выбор другого пути для `setup` создаёт другой профиль и обычно не является обновлением существующей службы.

## 3. Подключите клиент и запустите индекс

После создания конфигурации получите примеры подключения:

```sh
npm exec -- zorya-search client-config
```

Команда только печатает варианты, включая stdio; она не регистрирует MCP в Codex/редакторе и не подключает Search к чату. Отдельно добавьте выбранную конфигурацию в существующий клиент и выдайте ему только нужные права. Затем запустите начальную индексацию:

```sh
npm exec -- zorya-search index
```

При нестандартном расположении добавьте тот же `--config /absolute/path/runtime.json` в каждую из команд `client-config` и `index`. Индексация обновляет локальную базу и не изменяет исходные файлы. Для нескольких разрешённых репозиториев используйте `root-add`; не запускайте второй процесс-владелец с тем же каталогом базы.

Начните с `search_code` и `read_source`, если нужно найти текст и проверить текущие строки. `get_code_context` собирает ограниченные секции. Например, можно искать условие запуска инициативы, затем самостоятельно проверить исходник и тесты; поиск кандидатов дубликатов — другой необязательный запрос. Символы/ссылки и `includeLogical` есть только в текущих исходниках, не в архиве `v0.1.6`. Ни один из инструментов не является обязательным workflow.

Для Node.js-приложения можно использовать SDK вместо MCP. Запускаемый пример с локальной базой, проверкой текущего source snapshot и duplicate candidates находится в [README на английском](../README.md#sdk-example).

## Web и дополнительные профили

Архив `v0.1.6` может искать ссылки через Brave, читать заранее известную страницу при разрешённом web reader, классифицировать переданный текст и искать по явно переданным visual references при включённом профиле. Это независимые возможности, не обязательные шаги каждого code-поиска. Search не делает desktop capture и не загружает изображения по URL. Конфигурация web-поиска, классификатора и visual-профиля приведена в [CLI](cli.md), а границы разрешений — в [MCP](mcp.md).

Удалённый MCP требует инфраструктуру владельца: daemon остаётся на loopback, внешний HTTPS endpoint предоставляет reverse proxy, а проверку пользователей выполняет внешний OIDC/OAuth provider. Это не готовый hosted-сервис; локальные проверки не подтверждают подключение hosted ChatGPT или произвольного production IdP. См. [подробное руководство удалённого MCP](mcp.md).

## Индексируемые файлы и текущие исходники

Текущая политика индексирует `.md`/`.mdx` и выбранные форматы исходников и конфигурации. `.mdc` и `.txt` сейчас не индексируются. Отдельные embeddings для docs, rules и skills запрошены, но ещё не реализованы. Сравнение возможностей текущей ветки и доступного архива — в [руководстве по возможностям](capabilities.md).
