# MCP и локальный daemon

Wave 5.2 добавляет SDK-поверхности `@zorya/search/mcp` и `@zorya/search/daemon`. Daemon открывает один `SearchRuntime`; HTTP- и stdio-клиенты используют его индексы через transport. Stdio proxy подключается к daemon и не создаёт собственную БД или runtime. Сами импорты модулей не запускают службу и не открывают БД.

## MCP инструменты

Сервер предоставляет `list_roots`, `capabilities`, `index_status`, `index_repository`, `search_code`, `read_source`, `related_code`, `get_code_context`, `search_web`, `read_web_source` и `classify`. Корневые идентификаторы проверяются по выданному сервером allowlist. Схемы инструментов используют строгие runtime-схемы запросов. Индексация меняет индекс, но не файлы источника. Ответы сохраняют данные runtime о snapshot, профиле, источнике и деградации; сериализованный ответ MCP целиком, включая текстовое и структурированное представления, ограничен 1 MiB.

**MCP сам ничего не исправляет.** Он возвращает контекст и предположительные места, которые стоит проверить. Вызывающий агент сам проверяет вывод и решает, исправлять ли исходники. Текст кода, страниц и классификатора является недоверенными данными. MCP-адаптер не меняет prompt, модель, память, инструкции или действия вызывающего агента. Операционный `AbortSignal` MCP-запроса передаётся runtime, который удерживает ресурсы до физического завершения работы.

## Stdio

`runSearchMcpStdioProxy(endpoint, bearerToken)` создаёт stdio proxy для уже запущенного daemon. Proxy открывает MCP client connection к daemon, публикует пересечение удалённого списка с фиксированными 11 локальными Search-инструментами и передаёт вызовы и отмену. Имена, схемы, описания и hints берутся из локального контракта; неизвестные удалённые инструменты отбрасываются. Он не открывает собственную PGlite и не создаёт второй runtime. HTTP разрешён только для loopback endpoint; удалённый endpoint должен использовать HTTPS. Redirect запрещён, чтобы Authorization не пересылался на другой адрес. Endpoint и bearer передаются через аргументы SDK-функции; вызывающий launcher должен получать их из закрытого канала и не включать секрет в argv, URL или логи. Канал stdout принадлежит MCP-протоколу; диагностику процесса следует писать в stderr.

## HTTP daemon

`startSearchDaemon` открывает один runtime и привязывает Streamable HTTP на `/mcp` (можно задать другой путь). По умолчанию bind — `127.0.0.1`; сервер требует owner bearer длиной не менее 32 символов. Перед чтением/диспетчеризацией тела каждый запрос повторно проверяет bearer, Host и Origin. Размер тела MCP ограничен 1 MiB. Для удалённого bind требуются доверенный `authorize`, непустые allowlist Host/Origin и идентификатор principal от verifier. Caller не передаёт собственные права.

Современные запросы обслуживаются stateless handler SDK. Legacy Streamable HTTP использует ограниченный реестр до 64 transport connections с idle timeout 15 минут; запись привязывается к principal и снимку его root/operation grants. Это транспортные соединения, а не сессии агента. На GET, POST и DELETE bearer проверяется заново; закрытие daemon отменяет принадлежащие ему HTTP-запросы, закрывает transport-соединения и ждёт физического завершения работы. Тела ограничены 1 MiB и отдельной 30-секундной фазой чтения; операции используют общий настроенный бюджет runtime до 120 секунд.

HTTP daemon API этого этапа принимает owner bearer от вызывающего сервиса; он не создаёт секретный файл, не устанавливает процесс автозапуска и не добавляет CLI. Владелец обязан передавать секрет через закрытый канал конфигурации, а не URL, аргументы процесса или логи. Реальная OAuth Authorization Server не входит в пакет; custom header token не означает совместимость с OAuth или ChatGPT. Настройка клиента и подтверждение ChatGPT остаются отдельной работой.

## Статус проверки

Наличие экспорта и документации не подтверждает работу живого клиента. Typecheck/build или unit fixtures не заменяют loopback проверки реальным MCP SDK, реальные stdio subprocess, отмену обеих версий протокола, управление сессиями, сетевую изоляцию и внешние интеграции. Полную приёмку Wave 5.2 следует заявлять только по отдельным сохранённым квитанциям; ChatGPT auth/client, Windows ACL, внешние provider calls, CLI/setup и публикация не подтверждаются этим модулем.
