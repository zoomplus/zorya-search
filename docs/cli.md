# CLI Zorya Search

CLI предоставляет команды для локальной настройки, индексации и поиска, а также MCP stdio-вход к общему локальному владельцу базы. Пакет устанавливает исполняемую команду `zorya-search`; после сборки она находится в `dist/cli/entry.js`.

## Быстрый старт

```sh
npx --yes @zorya/search setup --root "$PWD"
npx --yes @zorya/search doctor
npx --yes @zorya/search index
npx --yes @zorya/search search --query "обработка запроса"
npx --yes @zorya/search context --query "где формируется ответ"
```

`npx` запускает пакет без глобальной установки. Если пакет установлен пользователем отдельно, те же подкоманды доступны через `zorya-search`.

Для большого workspace задайте явные пределы и исключите большие evidence-деревья до индексации. Например, Assistant workspace с 24 863 chunks на принятом snapshot:

```sh
npx --yes @zorya/search setup --root "$PWD" --exclude 'docs/evidence/**' \
  --max-files 20000 --max-chunks 50000 --max-scan-chunks 50000 --watch
```

Числа отражают профиль этой интеграции, а не универсальные рекомендуемые пределы. Для нескольких репозиториев используйте `root-add --root-id ID --root PATH`; укажите `--watch` для автоматической сверки каждого добавляемого корня. Корень выбирается явно и остаётся внутри allowlist конфигурации.

По умолчанию используется lexical-поиск без сетевых вызовов. `--code-env NAME` включает принятый preset для кода: `voyageai/voyage-code-4` размерности 1024 и `voyageai/rerank-2.5-lite`, который rerank-ит до 30 результатов и возвращает до 8. Конфигурация хранит только `mechanism.code.secret: { kind: "env", name: "NAME" }`; модель выбирается через общий `MECHANISM_RETRIEVAL_PRESETS` runtime preset. `--embedding-env NAME` оставлен как совместимый alias для code preset, если `--code-env` не указан. Код и поисковые запросы отправляются провайдеру для включённых операций embeddings/reranking.

Watch включается только явным `--watch`; `--watch-interval-ms N` задаёт интервал 250–60000 ms и требует этот флаг. Watch при запуске сначала индексирует выбранный корень, затем повторно сверяет изменения. При включённом облачном профиле изменённые фрагменты могут отправляться выбранному embedding-провайдеру. Без watch команда `index` выполняет только ручной проход. TTY-мастер отдельно спрашивает, включать ли автоматическую переиндексацию.

Владелец службы начинает отвечать после стартовой индексации настроенных watch-корней. Для watch CLI вычисляет общий срок из валидированных лимитов корней: 60 секунд плюс 20 ms на каждый разрешённый `maxFiles`, `maxChunks` и `maxScanChunks`, с пределом 45 минут; без watch остаётся 15 секунд. Конкурирующий первый клиент ждёт тот же срок. При его исчерпании launcher отправляет отмену своему child, runtime завершает начатые операции, а launcher присоединяет child и возвращает ошибку; MCP-инструменты не объявляются готовыми до фактической аутентификации.

Визуальный preset независим и включается только явным `--visual-env NAME`: `voyageai/voyage-multimodal-3.5`, 1024 dimensions, top 5. Он сохраняется в `mechanism.visual.secret` и не влияет на кодовый профиль; TTY-мастер также предлагает visual-only режим. Generic OpenAI-compatible endpoint доступен только как явно заданный custom profile: `--custom-embedding-endpoint HTTPS_URL --custom-embedding-profile ID --custom-embedding-model MODEL --custom-embedding-dimensions N --custom-embedding-env NAME`. Такой профиль конфликтует с code preset, чтобы не смешивать отдельные embedding spaces.

Существующий top-level reranker можно задать отдельно для web retrieval через `--web-reranker-model MODEL --web-reranker-env NAME`; classifier — через `--classifier-model MODEL --classifier-env NAME`; web discovery key — `--web-env NAME`. Все они сохраняются как environment references. Перед настройкой TTY-мастер сообщает, какие данные могут покинуть машину и что могут возникнуть расходы; сами ключи через prompt не принимаются. Каталожные модели сверены с сохранёнными официальными документами, live доступ, billing и данные реального провайдера не проверялись.

Пути конфигурации и данных по умолчанию находятся в пользовательских каталогах ОС и вне индексируемого корня. Для явного профиля службы задайте `--config PATH`, `--root PATH` и при необходимости `--data PATH`. Перед записью конфигурация проверяется общей строгой runtime-схемой; CLI не поддерживает отдельную схему credentials. Если конфигурация уже существует, setup завершится явной ошибкой и не заменит её; выберите новый путь либо отредактируйте профиль отдельно. Повторная установка пакета не удаляет индекс.

## Команды

- `setup` — создать конфигурацию; `--code-env NAME` задаёт переменную окружения code provider, `--visual-env NAME` опционально включает независимый visual profile. `--embedding-env NAME` — alias для code preset. `--watch [--watch-interval-ms N]` включает автоматическую повторную сверку. TTY-мастер предлагает lexical, code, visual и code+visual и спрашивает об opt-in watch.
- `doctor` — сообщить, существует ли конфигурация и отвечает ли подтверждённый локальный владелец. Проверка не вызывает внешние модели; поля провайдера остаются `not-run`.
- `index` — выполнить ручную индексацию первого настроенного корня. Если watch включён, runtime также выполняет стартовую индексацию и повторную фоновую сверку изменений.
- `search --query TEXT [--mode lexical|hybrid]` — выполнить поиск через MCP операцию Search.
- `context --query TEXT` — запросить ограниченный контекст через ту же операцию Search.
- `root-add --root-id ID --root PATH [--watch] [--watch-interval-ms N]` — добавить корень. Watch вступает в силу при следующем запуске службы; конфигурация не перезаписывается при активном владельце.
- `serve` — запустить локальную службу на loopback в foreground. При ручном запуске CLI сам создаёт приватные owner и control секреты; внутренние параметры секретных файлов используются только launcher-ом.
- `mcp` — предоставить MCP stdio и подключиться к общей локальной службе. Данные протокола идут только в stdout; диагностика — в stderr.
- `client-config` — вывести готовые варианты JSON `command`/`args`: `installed` запускает текущий установленный package entry через абсолютные `process.execPath` и путь entry и пригоден из другого cwd; `installedCodex` — соответствующий `codex mcp add`. `registry` и `registryCodex` используют `npx --yes @zorya/search@0.1.0` для опубликованной версии. Команда только показывает конфигурацию, не меняя профиль клиента.
- `service` — показать статус; `service --stop` отправляет отдельный случайный секрет по owner-specific локальному IPC каналу после проверки текущего daemon токена. PID из редактируемого descriptor не используется для остановки процесса.

Для help и version не читаются конфигурация, секреты или база. Диагностика возвращает структурированные значения; `doctor` различает установленный CLI, валидную конфигурацию, подтверждённый локальный сервис и фактическую проверку провайдера.

## Секреты и границы безопасности

Не передавайте секреты аргументами командной строки. Укажите имя переменной окружения в конфигурации, затем предоставьте её процессу владельца обычным способом. Файл владельца содержит локальные данные запуска, а bearer хранится в отдельном приватном файле в каталоге конфигурации; значения токена не включаются в URL, команды клиента и обычную диагностику. На POSIX CLI создаёт файлы с режимом владельца. На Windows этот режим не подтверждает ACL, поэтому защита зависит от ACL пользовательского каталога ОС.

Каталог владельца и БД должны располагаться вне индексируемых корней. Не копируйте их в проект. Сохраняйте резервную копию конфигурации и отдельную резервную копию каталога данных; восстановление выполняйте при остановленной службе, проверяя соответствие профиля/корня. CLI не очищает старые индексы и не удаляет неизвестные lock-файлы.

`mcp` подключает уже существующий MCP-клиент к локальному инструменту. Он не подключает автоматически текущий чат, не создаёт агента, не меняет prompt или модель и не применяет результаты кода. Локальный stdio endpoint не является hosted-интеграцией ChatGPT, OAuth или удалённой HTTPS-службой.
