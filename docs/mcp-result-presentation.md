# Представление результата MCP stdio

В source candidate [`af0a1ed`](https://github.com/zoomplus/zorya-search/tree/af0a1ed6faa9dd912798d28af8401bd8026964c6) добавлен необязательный режим представления результата локального stdio proxy для версии `0.1.8`. Он не меняет результат Search или его схему. Перед установкой проверь [страницу релиза `v0.1.8`](https://github.com/zoomplus/zorya-search/releases/tag/v0.1.8) на наличие нужного asset; для установки из npm отдельно сверь точную версию и tag в registry.

## Выбор режима

Поддерживаемый интерфейс — установленный CLI. Режим доступен только командам `mcp` и `client-config`:

```sh
npm exec -- zorya-search mcp --result-presentation structured
npm exec -- zorya-search client-config --result-presentation structured
```

Сгенерированная команда клиента включает выбранный режим. CLI не регистрирует клиента и не записывает его конфигурацию. Без параметра используется `legacy`. Это не SDK export; не подключай режим через приватный импорт из `dist`.

## Что меняется

В режиме `structured` proxy проверяет upstream ToolResult. Если текстовый блок разбирается как JSON и точно совпадает с plain-object `structuredContent`, текст только этого блока заменяется на `See structuredContent.` Сам `structuredContent`, source text, source hash и snapshot, независимые текстовые и нетекстовые блоки `content`, а также metadata сохраняются.

Проверка ограничена двумя пределами: `MAX_DUPLICATE_TEXT_LENGTH = 2 * 1024 * 1024`, то есть максимум 2 097 152 единиц UTF-16 в строке JavaScript (это не число байтов UTF-8); `MAX_COMPARISON_NODES = 100_000`, то есть максимум 100 000 сравниваемых узлов. Слишком длинный повторённый текст, превышение лимита сравнения, неподдерживаемые формы, некорректный JSON и несовпадающие payload остаются без изменений. Error result не преобразуется; при выброшенной upstream ошибке сохраняется прежний безопасный ответ proxy. В форматировании не участвуют Jev, вызовы модели, prompt, память, индексация или Search workflow.

Режим может помочь клиенту не получать повторный JSON body, если он уже читает `structuredContent`. Сохрани `legacy`, если consumer читает только текст `content`, ожидает полный дублирующий блок или не проверен с structured представлением. Параметр не регистрирует клиентов, не записывает конфигурацию, не меняет выбор модели и не принимает решения за клиента.

## Данные нативного caller

В пререгистрированной проверке проведены четыре нативных запуска агента с одной моделью `gpt-6-luna` и reasoning high. Каждый получил через реальный proxy один и тот же ToolResult из настоящего source: 172 строки, 6 828 байт. Во всех четырёх запусках совпали семь oracle fields; полный source и его identity сохранились в контексте клиента. На стороне producer использовался replay HTTP fixture; вызовов embedding, reranking и Jev было ноль. Это подтверждает передачу и представление данных для проверенной конфигурации, но не качество retrieval, работу production provider или улучшение конечных ответов.

Нативным клиентом был Codex CLI 0.163.0 на Linux. Hosted ChatGPT, Cursor, другие клиенты, multimodal runtime и более широкие device/provider сценарии не квалифицировались.

| --- | --- | ---: | ---: | ---: |
| 1 | legacy | 31 659 | 723 | 13 568 |
| 2 | structured | 29 729 | 700 | 18 048 |
| 3 | structured | 29 650 | 749 | 13 568 |
| 4 | legacy | 44 230 | 577 | 41 216 |

Показаны все запуски. В одном legacy запуске появился дополнительный utility `exec` и projected data; он сохранён в таблице и не исключается ради общего заявления о выигрыше форматирования. В описательном сравнении общего пути участвует один legacy и два structured запуска: входные токены — 31 659 против среднего 29 689,5 в structured (на 6,22098% меньше); последний запрос после tool — 17 869 против среднего 15 899,5 (на 11,02188% меньше). Первый запрос в обоих режимах составлял 13 790 токенов. При n=1 legacy и n=2 structured это только описательные наблюдения, не универсальная причинная оценка и не статистический вывод. Измеренный payload составлял около 14 923 байт в legacy и 7 380/7 439 байт в structured; это не означает уменьшение всего model context на 50%.

При наблюдавшемся cache расчётный Standard API-equivalent составил $0.00330834 для двух legacy запусков и $0.00381696 для двух structured. Использование cache различалось. Реальный invoice и service tier неизвестны; проверка не установила преимущество по оплате. Оценка $0.0071253 для всех четырёх запусков использует опубликованные [тарифы API `gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna), полученные 2026-11-02. Cached и reasoning tokens — подмножества, их не прибавляли повторно; оценка без cache контрфактическая и не является invoice.

## Интерпретация

Это необязательный выбор представления на transport уровне. Совпадение oracle fields и сохранение source identity не показывают, что клиент лучше решил задачу. Эти четыре запуска не показывают улучшения качества задач, экономии на оплате или превосходства MCP над обычным поиском и чтением.

Ранее выполненное frozen negative study остаётся без изменений: сравнивались 40 задач, два повтора и два режима (160 запусков); не пройдены все четыре предварительно заданных требования к качеству. Средняя оценка ответа составила 91,3 для обычного поиска/чтения и 90,975 для MCP Search; квалифицировано 72/80 и 70/80 запусков; по два critical flags в каждой группе; native input+output tokens — 23 699 031 и 43 446 185. Замороженная оценка warm cost составила $0.70863366 и $1.146069328. Эти значения относятся к отдельному исследованию и не пересматриваются проверкой stdio представления. Полная область и ограничения описаны в [сравнении MCP](mcp-comparison.md).

Наличие asset на странице релиза и версии в npm registry проверяются отдельно. Source gates, поведение package, CI и полная приёмка программы — разные уровни проверки. Этот гайд не утверждает, что полная цель принята.
