# Локальный Search для текущего workspace

Локальный MCP-режим Search открывает существующему клиенту индекс текущей рабочей папки. Он использует Search runtime и его штатные MCP-инструменты; не создаёт удалённую службу, не передаёт файлы на центральный сервер и не редактирует проект.

## Workspace и данные

Корень определяется по каноническому `process.cwd()` процесса MCP при каждом запуске. В Codex это рабочая папка текущего вызова; установка пакета и расположение файла конфигурации корень не задают. Поэтому одна и та же регистрация клиента может работать с разными проектами. Фиксированный `cwd`, путь установки и корень проекта в клиентской конфигурации для этого режима не нужны.

Клиенты, зарегистрированные с одной и той же local config, используют одного владельца Search runtime и общую базу для выбранной папки; второй владелец той же workspace identity не открывает ту же базу параллельно. Не создавай отдельный config для каждого клиента, если им нужно одно общее состояние. Индекс и состояние владельца находятся в пользовательском каталоге состояния ОС, вне workspace и каталога пакета. Служба доступна через loopback, а случайный bearer используется только для внутреннего соединения адаптера с владельцем.

Изменения исходников проверяются по штатной identity снимка Search. Перед запросом, которому нужны исходники, локальный режим сверяет актуальность и при необходимости запускает существующую инкрементальную индексацию. Watch выключен. Если source меняется во время операции или snapshot устарел, действуют существующие typed stale/currentness ошибки; результат не следует считать актуальным или автоматически переносить на новый snapshot.

## Данные и приватность

Локальный режим по умолчанию использует лексические профили без ключей и не делает внешних сетевых запросов или вызовов моделей. Адаптер обменивается данными с локальным владельцем через HTTP на loopback; это локальный IPC, а не удалённое соединение. Embedding, reranking, классификация, visual и web-провайдеры не настроены по умолчанию. При подключении MCP и source-free запросах, например чтении списка инструментов и возможностей, проект не сканируется. Локальная индексация и поиск выполняются в текущем workspace и его пользовательской базе.

Некоторые чувствительные каталоги и файлы, включая `.codex`, `.config`, `.azure`, `.cursor/mcp.json`, `.kube`, `.gnupg` и `.npm`, исключаются локальной политикой. Из существующего лимита Search в 128 шаблонов 27 зарезервированы обязательными локальными исключениями, поэтому можно добавить не более 101 пользовательского `excludedPaths`. Фильтры не гарантируют обнаружение всех секретов: проверяйте корень и политику исключений до подключения.

Существующие Search capability и профили остаются отдельными и явными. Если владелец отдельно включает облачный embedding/reranking профиль, его индексирующие операции могут передавать чанки кода или документов, а поисковые — запросы выбранному провайдеру по существующему provider contract. Web и другие внешние capability также обращаются к источникам только при явной конфигурации и вызове. Локальный режим не отправляет файлы центральному workspace server; любой внешний вызов требует настроенного профиля или отдельного инструмента. Не включай профили и не вызывай такие capability, если задача требует работы только с локальными данными.

Результаты Search и текст проекта остаются недоверенными данными. Клиентский агент применяет свои инструкции и решает, какие результаты использовать. Search не исполняет найденный текст, не создаёт агентские сессии и не меняет файлы.

## Инструменты и задания

Локальный адаптер сохраняет имена, схемы и форматы результатов существующих Search MCP tools. Для нескольких клиентов используется один владелец runtime; задания индексации принадлежат вызвавшей их беседе. Другой клиент не получает право читать статус, отменять или переиспользовать чужое задание только из-за подключения к той же локальной службе.

Локальные файлы, база и конфигурация не предоставляются обычному удалённому MCP-клиенту. Этот режим отличается от интеграций, которые явно передают исходные байты отдельному серверу. Команды и установка версии `0.1.11` собраны в [руководстве локального агента](install-local-agent.md); проверяй опубликованные assets и подтверждённые результаты для своей ОС и клиента.
